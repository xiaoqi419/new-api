# Outcome

恢复 GMPay/EPUSDT 的自动网络费用估算可用性：当主价格源限流或暂时不可达时，内置估算器在服务器端使用受控的备用公开价格源，并通过短期成功报价缓存避免状态探测造成请求风暴。用户仍看到服务端计算的非负网络费用和总额；没有可信价格时继续安全失败。

# Scope

- 修复内置 GMPay 网络费用估算在 CoinGecko 返回 429/5xx/网络错误时直接失败的问题。
- 为 TRON、Ethereum、BSC 和 Solana 的 USD/CNY 原生资产价格提供服务器端、固定白名单的备用源；按主源优先、备用源顺序尝试，成功结果记录真实来源和时间戳。
- 为同一网络/币种/结算币种增加有界的短期成功价格缓存和并发合并，减少后台状态探测对公共源的重复请求；缓存命中仍重新检查价格年龄和报价 TTL。
- 维持现有链上 RPC 估算、金额拆分、报价绑定、失败关闭和管理员配置界面，不新增管理员必须填写的参数。
- 增加针对限流回退、CoinPaprika 响应解析、缓存命中及过期失败的回归测试，并同步必要的变更记录。

# Non-goals

- 不把 429 转换为零费用，不绕过价格年龄、金额上限或来源主机白名单。
- 不依赖 GMPay/EPUSDT 未提供的手续费字段、订单金额或汇率差，不修改支付网关、生产数据库、Redis 或订单数据。
- 不开放任意用户/管理员输入价格 URL，不引入需要密钥的行情服务或交易所账户。

# Acceptance examples

- A1：国际站主价格源返回 HTTP 429 时，受支持的 GMPay 网络在一次受控请求内自动尝试备用源；备用源返回匹配资产、USD/CNY 和新鲜时间戳时，状态恢复为可估算，quote 的 `PriceSource` 标明备用主机。
- A2：备用源响应的资产、币种、数值或时间戳缺失/不匹配/过期时，估算继续 fail-closed，不创建零费用或负费用订单。
- A3：连续的同网络/币种/结算币种估算在短缓存 TTL 内只产生一次行情请求；缓存命中仍受严格价格最大年龄和 quote TTL 约束，过期后重新取源。
- A4：现有 TRON/EVM/Solana 链上估算、金额不变量、回调幂等和 Legacy EPay 行为保持不变；管理员无需新增配置。
- A5：聚焦 Go 测试覆盖主源限流回退、备用源解析、缓存及 fail-closed 边界；相关前端/构建检查不因本修复回归。

# Constraints and invariants

- 公开行情端点只能访问代码内固定 HTTPS 主机白名单；响应体大小、请求超时和重试次数继续受现有上限约束。
- 备用源的价格必须包含可解析的 RFC3339/Unix 时间戳，且不超过现有 `priceMaxAge`；不因供应商免费计划的平均更新周期而放宽安全年龄上限。
- `total_amount = base_amount + fee_amount`，费用必须有限、非负并受单笔/总额上限限制；行情不可用时拒绝报价。
- 不修改数据库 schema 或持久化生产配置；缓存只存在进程内且可丢失。

# Decisions

- 采用“主源 CoinGecko → 受控备用源 CoinPaprika”的顺序；备用源仅在主源请求/响应失败时使用，成功后在证据中标注实际来源。保持严格时间戳校验，宁可暂时不可用也不使用陈旧价格。
- 缓存按网络、结算币种和原生资产分区，TTL 短于价格年龄上限，并在命中时再次校验时间戳；用进程内互斥避免并发状态探测重复打行情请求。
- 不修改通用自定义估算器的多源共识语义；本修复只扩展内置自动估算器的受控源回退。

# Open questions

- 无。用户已确认自动链上费用估算的总体口径；本 change 仅修复已发现的生产可用性缺陷，保持原有失败安全策略。

# Verification expectations

- `go test -count=1 ./service -run 'BuiltinNetworkFee|NetworkFeePrice'` 及相关 controller 测试。
- 必要时运行受影响后端包测试、`git diff --check`；不执行生产部署或数据库写操作。
