# Outcome

已从登录后主导航隐藏的功能，在聚合页面的二级标签和同类导航入口中也不再重复展示；功能实现、路由和直接访问能力继续保留。

# Scope

- 让现代版聚合页面的导航数据复用同一套隐藏 URL 策略。
- 在财务中心隐藏仍指向 `/finance/groupbuy` 的“拼团大厅”标签。
- 保留钱包、发票、幸运抽奖及其他未标注的财务中心标签和原有顺序。
- 检查现代版和经典版中是否还有指向七个已隐藏目的地的二级导航、标签或快捷入口；只处理真实存在的重复入口。
- 在二开生产仓库最新代码内容上本地开发和验证。

# Non-goals

- 不删除或禁用拼团大厅、用户排行、兑换码、订阅、拼团、返现、身份认证管理的页面、路由、接口、支付流程或数据。
- 不隐藏与管理员入口不同的用户侧能力，例如个人身份认证、邀请记录、钱包充值或订阅购买组件。
- 不修改经典版不存在的聚合财务中心结构。
- 不部署线上环境，不修改生产数据库或运行配置。

# Acceptance examples

- A1: 管理员进入现代版财务中心时，顶部只显示钱包、发票和幸运抽奖，不再显示“拼团大厅”。
- A2: 财务中心剩余标签保持原有顺序、选中态和跳转行为，页面不出现空白标签或布局错位。
- A3: `/finance/groupbuy` 路由、`GroupBuyHall` 组件及相关业务代码仍存在，直接访问继续由原路由和权限逻辑处理。
- A4: 当前现代版和经典版的二级导航、标签及快捷导航中，不再重复展示指向七个已隐藏目的地的入口；未标注入口保持可见。
- A5: 受影响的单元测试、类型检查、lint、format、现代版生产构建和 Git diff 检查通过。
- A6: 本 change 只修改本地二开代码和测试，不接触生产数据库、生产配置或线上部署。

# Constraints and invariants

- 使用稳定 URL/section ID 判断可见性，不根据翻译后的中文或英文标签判断。
- 隐藏规则作用于导航数据，不从 section registry 或路由树删除 `groupbuy`。
- `xiaoqi419/new-api` 是唯一二开生产基线；`QuantumNous/new-api` 只作为受控上游同步源。
- 保留其他任务和用户已有改动，不从旧 `secondary-dev` 工作区复制历史脏修改。

# Decisions

- 用户明确要求不仅隐藏主导航，还要隐藏截图中聚合页面内部重复出现的对应入口。
- 继续沿用上一轮“隐藏但不删除功能”的产品决定，直接 URL 访问保持可用。
- 仓库检索确认当前截图问题的重复目的地是财务中心的 `/finance/groupbuy` 标签；用户侧不同能力不按名称相似扩大隐藏范围。
- 当前分支代码树与合并后的二开 GitHub `main` tree SHA 一致，再从该本地基线继续开发。
