# Outcome

将现有登录与注册入口重设计为参考图所示的暗色科技感双栏体验：在克制的点阵背景中放置居中的完整认证界面，左侧表达统一接入多模型的产品价值，右侧分别承载紧凑、清晰的登录或注册表单，同时保持现有全部真实认证能力。

# Scope

- 重构桌面端登录页的背景、双栏主面板、左侧品牌叙事区和右侧登录区。
- 注册页复用同一套背景、居中双栏主面板和品牌叙事区，右侧继续承载独立注册表单。
- 使用项目现有蓝色/青色主题变量和中性色，不照搬参考图的荧光绿色，也不引入旧粉色强调色。
- 左侧保留一次品牌展示，并提供两行价值标题、简短说明、Claude/Codex/Gemini 等模型入口提示和页脚信息；不显示额外的产品能力胶囊标签。
- 右侧提供欢迎标题、始终双向可见的登录/注册分段入口，以及现有登录表单、第三方登录、通行密钥和协议说明。
- 为平板和手机提供无横向滚动、表单优先的单栏布局。
- 为新增文案补齐前端国际化，并新增一条对应的 changelog。
- 增加与布局、条件显示和响应式行为风险相称的前端回归测试。

# Non-goals

- 不改变任何认证 API、OAuth 跳转协议、2FA、验证码、会话或登录后重定向逻辑。
- 不把登录和注册表单合并为单页状态机；现有 `/sign-in` 与 `/sign-up` 路由保持独立。
- 不重设计找回密码、OTP 和 OAuth 回调页面。
- 不修改后台的登录页配置结构，也不新增图片生成资源或第三方动画依赖。
- 不提交、合并、推送或正式部署，直至用户验收候选界面。

# Acceptance examples

- A1：在宽度不小于 1024px 的登录页中，可见暗色点阵背景和居中的有边界双栏主面板；主面板不会贴满整个视口，也不会出现大块无意义留白。
- A2：桌面左栏只展示一次站点品牌，并可见醒目的两行主标题、简短说明、Claude/Codex/Gemini 与更多模型提示；不显示额外的产品能力胶囊标签，内容层级使用当前站点数据和主题。
- A3：右栏可见紧凑的登录容器、欢迎标题、账号密码字段、忘记密码入口和主要登录按钮，控件对齐稳定，长英文文案不溢出。
- A4：登录页与注册页始终同时显示“登录 / 注册”分段入口，并可在现有两个独立路由间双向切换；后台注册开关继续控制注册服务，不再用于制造两页不对称的导航。
- A5：后台启用的密码登录、Passkey、GitHub、Discord、OIDC、LinuxDO、Telegram、微信和自定义 OAuth 仍按现有状态条件显示并走原有处理逻辑；未启用的方式不显示。
- A6：账号密码登录仍执行 Turnstile/点击验证码校验，并在服务端要求时跳转 2FA；登录成功后的 redirect 参数仍生效。
- A7：在手机和平板宽度下页面切换为表单优先的单栏布局，品牌信息适度收敛，无横向滚动、遮挡或不可触达控件。
- A8：页面不依赖装饰动画表达信息；当前不额外添加装饰动画，后续若加入动画仍必须尊重 `prefers-reduced-motion`。
- A9：页面颜色来自现有主题语义变量及其中性色，不出现硬编码旧粉色，也不照搬参考图的荧光绿色。
- A10：新增用户可见文案具备中英文翻译，changelog 最新位置包含本次登录页重设计记录。
- A11：注册开启时访问 `/sign-up`，桌面端可见与登录页一致的有边界双栏主面板和单次品牌展示，右侧紧凑显示现有注册字段与创建账户按钮；移动端表单优先且无横向溢出，登录/注册入口可在两个独立路由间正常切换。

# Constraints and invariants

- 遵守 React 19、TypeScript、Tailwind、TanStack Router 和现有 Auth 组件约定。
- 复用现有 `UserAuthForm`、`OAuthProviders`、`AuthTabs`、`TermsFooter` 及认证 hooks，视觉改造不得复制认证业务逻辑。
- 站点名称、Logo、登录页标题/描述和统计项继续读取现有系统配置；配置缺失时使用可国际化的默认文案。
- 装饰元素必须 `aria-hidden`，交互控件保持可访问名称、键盘操作和清晰焦点状态。
- 保留用户及其他代理已有改动；本 change 在独立 worktree 中实现。

# Decisions

- 采用参考图的“外层点阵画布 + 居中双栏面板 + 右侧内嵌登录卡片”信息架构。
- 视觉语言使用深色石墨背景、蓝青主色、细描边和微弱光效，避免拓扑图、大面积渐变装饰、旧粉色和荧光绿。
- 桌面左栏承担产品叙事，右栏只承担认证操作，避免重复展示品牌。
- 移动端以登录操作为第一优先级，压缩或隐藏桌面叙事内容。
- 登录能力完全沿用现有实现；登录/注册分段入口在两页始终对称显示，后台注册开关仍是注册服务的最终权限来源。
- 注册页与登录页复用同一认证体验外壳，但继续使用独立路由和现有注册表单，不复制注册业务逻辑。
- 参考图为唯一新增视觉素材来源；不调用外部 image-to-code 或图像生成服务。

# Verification expectations

- 运行登录与注册入口相关 Vitest/React Testing Library 测试。
- 运行受影响文件 lint、`bun run typecheck` 和 `bun run build`。
- 在桌面、平板和手机视口检查布局、溢出、OAuth 条件显示与 reduced-motion 行为。
- 独立只读 Verifier 逐项验收 A1-A11，并以实际代码、测试结果和浏览器检查结果为依据。
