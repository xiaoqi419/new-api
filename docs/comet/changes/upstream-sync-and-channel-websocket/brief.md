# Outcome
在已发布 c9c6da071 基线上继续完成 WS 长耗时排查与优化，并在日志顶部增加当前用户今日缓存率和总 Token。

# Scope
- 保留已合入主线的上游兼容更新、WS 会话复用、客户端 Responses WS、SSE 桥接和防重复请求行为。
- 对比 New API、CPA 和客户端时间，区分上游生成、流停顿、终止事件之后的本地拖尾；有证据的本地缺陷应修复并验证。
- TPM 右侧显示缓存率和总用量，当前登录用户当天全部消费日志聚合，不受列表筛选、分页影响。
- 当天按浏览器本地自然日；缓存率按缓存读取 Token 合计除以有效输入 Token 合计，总用量为输入和输出 Token 合计；无有效缓存数据用占位符。

# Non-goals
- 不重新开发已发布的上游更新和 H5；不降低模型推理力度、截断回答或伪造首字指标。
- 不改变凭证固定出口代理，不启用直连，不改变计费和模型设置。

# Acceptance examples
- A1: 现有 WS/SSE、连续会话和防重复请求测试通过。
- A2: 今日汇总仅当前用户，按自然日边界统计，列表筛选和其它用户数据不影响结果。
- A3: 缓存率加权汇总正确，总 Token 不重复计算缓存，空数据和历史缺失数据可读。
- A4: 桌面日志顶部顺序为用量、RPM、TPM、缓存率、总用量；窄屏可读，支持翻译和隐私遮罩。
- A5: 记录长耗时样本和分阶段证据，明确可归因与尚无法归因部分；本地修复需有回归验证，不用改变生成参数制造改善。
- A6: 受影响后端测试、前端类型检查/测试/构建通过；发布通过主线 PR、CI、不可变镜像，两站代码一致。

# Constraints and invariants
- origin/main 是生产基线。保留旧工作区及其未提交内容。
- JSON 使用 common 包；SQLite/MySQL/PostgreSQL 兼容，relaykit 独立。
- 不将首事件当真实首文本，不将已收到终止之后的耗时混同生成时间。
