## 64位额度数据库升级前置条件

官方 `a073f74b` 的契约是：新实例按 `BIGINT` 建立用户额度列，旧 MySQL/PostgreSQL `INT` schema 在启动前被拒绝，由运维先完成一次可回滚的类型迁移；应用不会在启动时自动改写已有钱包数据。该约束不新增表或列。

- MySQL（先备份并在维护窗口执行）：`ALTER TABLE users MODIFY quota BIGINT NOT NULL DEFAULT 0, MODIFY used_quota BIGINT NOT NULL DEFAULT 0, MODIFY aff_quota BIGINT NOT NULL DEFAULT 0, MODIFY aff_history BIGINT NOT NULL DEFAULT 0;`
- PostgreSQL（先备份并确认无超出 BIGINT 的值）：`ALTER TABLE users ALTER COLUMN quota TYPE BIGINT USING quota::bigint;`，对 `used_quota`、`aff_quota`、`aff_history` 分别执行同样的 `ALTER COLUMN ... TYPE BIGINT USING ...::bigint`。
- SQLite 不执行该启动拒绝检查；其动态整数存储沿用现有迁移流程。
- `SKIP_64BIT_QUOTA_SCHEMA_CHECK=true` 只用于临时诊断，不能作为生产迁移替代。迁移后重新启动，`ensureUserQuotaColumns` 会按实际方言读取列类型确认已满足约束。
