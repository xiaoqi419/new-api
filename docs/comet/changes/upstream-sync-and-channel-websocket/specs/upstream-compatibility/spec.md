# 上游兼容同步完整规格

## 来源

- 输入仓库：`https://github.com/QuantumNous/new-api`，官方 `upstream/main`。
- 目标：`v1.0.0-rc.33`，提交 `eb99ab1b40343c3317bb47981cccdbb2b159a5fa`。
- 共同基线：`2d8e50bf36e94200b809dfb39e73624ec48b1e23`。

## 行为

1. 逐项审查共同基线之后的官方提交，记录提交、路径、行为、风险、冲突处理和验证证据。
2. 将稳定的安全、协议兼容、数据库兼容、性能、计费完整性、模型/relay 和明确用户功能合入 fork；用户已确认第二批模型/协议/计费改动全部实现。
3. 对与 Torch AI 二开同一行为链的文件做三方语义合并，保留两侧可同时满足的契约；不能同时满足时回到 Shape，不擅自覆盖。
4. 保留现有支付、充值、订阅、GMPay、H5、低余额提醒、视频、代理、双前端和保护性品牌/元数据。
5. 排除官方发布说明标注为实验性、会替换架构或删除现有二开模块的变更；密码传输加密和 int32 迁移按用户确认纳入，但不采用会覆盖二开模块的整段重构。
6. 不新增数据库 schema；数据库、Redis、JSON wrapper、quota safety 和 relaykit 独立性不回退。

## 验收

- 合并结果可从官方目标提交和 fork 基线追溯，工作树无冲突标记和意外删除。
- 官方纳入项的行为测试通过，二开能力的回归测试和关键前端页面保持。
- root/relaykit/前端检查记录真实结果，未运行项目明确列为限制。
