# Outcome

为用户提供可靠、可配置的低额度邮件提醒。管理员可以按站点当前额度显示单位配置全局开关、阈值和邮件模板，用户可以用个人阈值覆盖全局值；提醒按余额周期只发送一次，并在余额恢复后重新武装。

# Scope

- 在系统设置中增加低额度提醒开关、全局阈值、内置/自定义模板选择、模板预览和测试收件邮箱/发送按钮。
- 阈值输入和展示跟随站点当前额度单位：USD、CNY、CUSTOM 或 TOKENS。保存时规范化为内部单位，读取时按保存时的单位语义展示，汇率或站点显示单位变化不得改变已保存配置的含义。
- 保留用户通知设置中的个人阈值；非空个人值覆盖全局值，空值继承全局值。
- 使用现有 SMTP 和通知发送链路发送邮件，测试邮件复用 SMTP 配置但不创建用户提醒状态。
- 钱包余额和订阅余额分别维护提醒周期状态。权威结算、充值、退款或管理员调整后的余额从不低于阈值变为低于阈值时创建一次提醒；持续低于阈值不重复发送；恢复到阈值以上后重新武装。
- 使用现有数据库系统任务框架对失败或错过的提醒进行补偿扫描，并提供可审计的发送结果和错误日志。
- 为新增后端行为、跨数据库迁移、模板验证、API 和前端交互补充测试及 i18n/changelog。

# Non-goals

- 不引入 Novu、Asynq、gocron、listmonk、Lago 或其他外部通知/调度平台。
- 不改变现有额度扣费、订阅结算、SMTP 连接配置或其他通知渠道的语义。
- 不在本 change 中部署生产环境，不依赖 GitHub CI，不修改受保护的项目身份信息。
- 不发送持续低余额的重复邮件，不提供营销群发或任意用户列表群发能力。

# Acceptance examples

- 管理员开启提醒并输入 `1`：USD 站点保存为 `$1` 的规范化值，CNY 站点保存为 `¥1` 的规范化值，CUSTOM/TOKENS 站点分别保存为一个自定义货币单位/一个 token 单位。
- 管理员关闭提醒后，即使用户余额低于阈值也不创建或发送提醒；重新开启后只对新的低余额周期生效。
- 用户个人阈值为非空值时使用个人值；个人阈值留空时使用管理员全局值。
- 内置模板可以切换并预览；自定义模板只允许白名单变量（`username`、`remaining_quota`、`threshold`、`currency_symbol`、`top_up_url`、`site_name`），未知变量在保存和发送前被拒绝。
- 测试收件邮箱为空、格式非法或 SMTP 发送失败时返回明确错误；成功时只发送测试邮件，不改变任何用户的提醒状态。
- 权威余额由高于或等于阈值变为低于阈值时，重复扫描和并发请求最多创建一个发送记录；发送失败可由系统任务重试，成功后不重复发送。
- 充值、退款或管理员调整使钱包余额回到阈值以上后，下一次再次跌破阈值可以重新提醒；订阅状态独立验证同样规则，钱包恢复不会重置订阅状态，反之亦然。
- SQLite、MySQL 5.7.8+ 和 PostgreSQL 9.6+ 均可完成迁移、读写提醒状态和并发去重查询。

# Constraints and invariants

- 全局阈值默认是当前显示单位的 `1`，不再使用旧的内部默认值 `1000`。
- 保存的阈值必须携带足以还原其原始显示单位语义的规范化信息，不能因后续汇率或显示单位变化而漂移。
- 阈值和余额比较使用安全的额度转换函数，拒绝 NaN、Infinity、负数及超出数据库 int32 范围的输入。
- 一次低余额周期只允许一个提醒状态从 armed 转为 pending/sent；状态更新必须使用 GORM 兼容 SQLite、MySQL、PostgreSQL 的事务和约束。
- 未配置通知邮箱时保持现有跳过行为并记录原因；测试邮件只能使用管理员明确输入的收件地址。
- SMTP 凭据、用户密码、私钥、令牌和连接串不得写入 brief、spec、日志或测试快照。

# Decisions

- 采用现有 Option 配置、UserSetting、NotifyUser、SMTP 和 system-task 框架；新增持久化提醒状态和模板渲染/校验层。
- 管理员全局配置是默认值，用户个人阈值显式配置时覆盖，留空继承。
- 默认阈值为显示单位 1；管理员输入和 UI 展示使用站点当前货币/额度单位，后端保存规范化内部值及单位语义。
- 内置模板加自定义模板；自定义模板支持主题、HTML 正文和纯文本正文，并限制变量白名单。
- 钱包和订阅各自维护 armed/low/sent 生命周期，不共享去重状态。
- 低余额触发以权威结算/调整后的余额为准；系统任务负责补偿和重试，不改变一次周期一次提醒的约束。
