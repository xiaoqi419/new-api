# 密码找回认证体验规格

## 完整目标

忘记密码与密码重置确认是公共认证流程的一部分，必须使用和登录、注册一致的认证体验：暗色点阵背景、桌面双栏容器、品牌叙事区、受限宽度的表单区以及基于当前主题 token 的边框、阴影和控件颜色。移动端隐藏桌面叙事区并在表单区显示品牌标识，表单内容保持可读且可操作。

## 页面语义与响应式

- 共享认证体验外壳支持 `forgot-password` 和 `reset-password` 页面标识，并为表单区域提供与页面一致的可访问名称。
- 两个页面均在根容器保留横向溢出保护，面板、品牌区、表单区和卡片内容均允许窄屏收缩。
- 桌面面板保持现有双栏阈值、最大宽度、点阵装饰、品牌叙事和主题色；不新增独立视觉主题或覆盖全局亮色设置。
- 320px 及以上视口中，长中文和英文标题、说明、表单标签、提示、按钮与状态文案不得使页面产生横向滚动或遮挡控件。

## 业务行为兼容

- 忘记密码页面继续使用现有表单 schema、邮件发送 API、Turnstile、点击验证码、倒计时和 toast 反馈；视觉改动不得改变请求参数、触发顺序或禁用条件。
- 重置确认页面继续从既有路由搜索参数读取 email 与 token，保留无效链接提示、重置请求、倒计时、生成密码、复制和返回登录流程。
- 登录、注册、OAuth、2FA 和其他认证回调页面不因该 change 切换外壳或修改业务行为。

## 国际化与变更记录

- 页面继续通过 `useTranslation()` 使用已有的“Forgot password”“Reset password”及重置反馈键，所有现有七种语言均须可解析。
- changelog 最新条目记录找回与重置页面的可见体验统一。

## 验证契约

- 组件回归测试覆盖两个页面接入共享体验外壳、正确页面语义、关键控件保留及窄屏横向溢出保护。
- 静态搜索确认两个页面不再使用旧 `AuthLayout`，并保留原有业务 API、验证码、token 与导航调用。
- 受影响的聚焦测试、格式检查、lint、类型检查和生产构建必须通过。
