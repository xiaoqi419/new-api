# 充值活动准确档位折扣设计

日期：2026-11-11
状态：用户已确认准确档位规则；实现前书面方案复核。
基线：origin/main 51926702136c036ac1bd130f2b79dfa4a4fcf8ce。
工作分支：codex/recharge-discount。

## 已确认需求

在 /recharge-bonus 管理页面选择赠金模式或折扣模式。折扣模式支持多个准确金额档位；配置充值100、9折，表示到账100、商品应付90。充值150不匹配100档；不按门槛匹配、不按倍数匹配。用户选择充值档位，活动模式由管理员统一选择。

## 配置和展示

扩展 TopUpBonusCampaign，缺省 mode 为 gift，兼容旧配置；mode 支持 gift、discount。沿用 enabled/start/end 和最多20档限制。gift 保持现有实付门槛与赠金逻辑；discount 的档位金额是充值面额，折扣按付款比例保存（9折为0.9）。折扣金额档位为正整数，以匹配现有充值接口整数金额约束；折扣严格大于0、小于1，最多四位小数；重复档位和非法数值由后端拒绝。

界面使用现有表单和选择组件；折扣输入展示“折”，支持9、8.5等；每档显示到账面额与折后价格预览。切换模式时保留草稿中的两种参数，保存仅提交当前模式有效字段。用户充值页补充活动档位按钮和准确匹配说明，实付以服务端报价为准。新增文案补齐七种语言，更新内置更新日志。

## 金额、支付与兼容

折扣在现有币种、单价和用户组价格换算后作用于商品应付金额；正常单价1、分组倍率1时，100×0.9=90。支付通道已有手续费规则保持，确认界面分开展示商品金额与手续费，避免将通道费用误报为折扣失效。

活动折扣不与已有 AmountDiscount 相乘；折扣活动有效期间，充值金额折扣由活动准确档位独占，未匹配金额为原价。赠金模式及活动关闭时继续使用原有金额折扣规则。代理预充值、拼团、订阅和固定价格商品不自动纳入钱包活动。

报价和支付创建共用准确匹配逻辑；真实支付渠道的收款参数必须与报价一致。Stripe 现有报价和 Checkout 固定 Price ID 使用不同路径，必须同时适配真实收款，并保留原有到账单位语义；不能只改报价。Creem 固定商品不伪装成可变价充值档位。易支付、GMPay、支付宝、微信、Waffo/Pancake 的普通钱包充值路径分别核对。

订单存储实际支付金额和到账面额，并保存活动模式、折扣及赠金快照。回调按订单快照到账，不读取当前活动重算；没有快照的历史订单保留旧结算逻辑。支付回调金额校验、幂等、代理钱包扣款、挂单补发和钱包溢出保护继续有效。返利遵循现有业务定义，新增折扣不得把赠金或优惠差额当作实收；相关账本与通知明确区分实付和到账。

## 验收

- 配置100/9折、200/8.5折：相应商品应付90、170，到账100、200。
- 99、101、150、300均不匹配；不存在门槛或倍数优惠。
- 关闭、未开始、过期活动按原有定价；有效折扣不叠加已有金额折扣。
- 活动在下单后修改、切换到赠金或过期，原订单仍按快照结算；重复回调不重复到账。
- 非法折扣、重复档位、非有限数字和超限金额被拒绝；金额以decimal计算并在支付边界舍入。
- 前端模式切换、多档新增删除保存、折扣预览、服务端报价和支付创建一致；旧赠金活动可读取保存。
- 针对模型和支付适配编写回归，执行根模块相关测试、vet/build，前端类型检查、相关测试、lint、i18n同步和构建；浏览器验证桌面和移动端。

## 交付边界

当前为本地功能开发和验证；不自动开启线上活动、不虚构实际折扣档位，不调用真实付费支付接口。发布沿用仓库PR、合并和不可变构建流程，执行发布前另行确认发布范围。
