# 思考等级转为上游模型后缀

部分 OpenAI 兼容上游用 `gpt-5.6-sol-low` 这样的模型名表示思考等级，而客户端发送的是标准主模型名和独立的思考参数。渠道设置 `reasoning_effort_to_model_suffix` 用于连接这两种接口。

## 设置

在渠道编辑的高级设置中开启“思考等级转为模型后缀”。默认关闭，只影响开启的渠道。渠道模型列表和价格设置使用客户端请求的主模型名，例如 `gpt-5.6-sol`。

Chat Completions 客户端请求：

```json
{
  "model": "gpt-5.6-sol",
  "reasoning_effort": "low",
  "messages": [{"role": "user", "content": "你好"}]
}
```

该渠道发往上游的请求：

```json
{
  "model": "gpt-5.6-sol-low",
  "messages": [{"role": "user", "content": "你好"}]
}
```

Responses 请求使用 `reasoning.effort`，转换后移除 `effort` 并保留其他 reasoning 属性。支持 `none`、`minimal`、`low`、`medium`、`high`、`xhigh`、`max`；具体上游是否支持某等级仍取决于其账号配置。没有指定等级时不追加默认后缀。此功能不处理括号模型语法，也不自动生成 `-fast`。

## 计费与透传

转换出的上游后缀不改变客户端主模型的计费身份。只需给主模型配置适当的输入、输出、缓存价格或阶梯表达式，按实际上报用量结算。此功能不会自动设置价格，也不保证供应商对各等级使用相同成本。

同时启用请求体透传和后缀转换，表示允许这项明确的模型/effort 字段修改；其余未知字段应保留。只有透传、没有启用后缀转换时，完整模型名保持不变，渠道测试也应遵循该规则。

## 验证

使用主模型加标准思考参数调用，并核对上游收到的模型名称与 New API 消费日志的计费模型。后台渠道测试可选择思考等级，默认不覆盖；Chat 和 Responses 测试会带上对应标准参数，与实际转发使用相同转换规则。未开启的渠道保持既有行为。
